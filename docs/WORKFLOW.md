# 通用交付工作流

这份流程约束 Agent / 设计师如何从来源材料得到可验证的 Figma 组件和页面。
任何项目都按五个阶段推进，不把特定客户、品牌或页面数量写入运行时。

## 阶段 1：来源确认

接受以下任一种来源：

1. 用户指定的 Figma URL，且当前身份拥有查看权限。
2. 用户复制到自己账号或本地 Figma Desktop 的文件。
3. 用户导出的 `.fig` 文件。
4. 按页面导出的 PNG、JPG 或 PDF。
5. 混合来源，例如 Figma 中有部分图层，历史页面只有截图。

若无法访问原文件，明确要求用户复制文件或导出截图。不要反复尝试需要付费权限
的接口，也不要声称仅凭文件名完成了视觉分析。

必须记录：

- 来源文件名和 URL（如适用）。
- 来源类型和访问状态。
- 总页面 / 截图数量。
- 视口尺寸和平台。
- 无法读取或缺失的页面。

输出：`PROJECT_BRIEF.md` 和初版 `SOURCE_INVENTORY.md`。

### 阶段门

- 每个来源页面都有稳定 ID。
- 已知哪些页面是图片、真实图层或混合结构。
- 用户要求的目标范围明确。

## 阶段 2：页面与组件拆解

逐页观察并记录：

- 所属流程、前后关系和进入条件。
- 页面状态：默认、加载、空态、错误、成功、权限、确认等。
- 全局导航、页面 Chrome 和固定操作。
- 重复三次以上或承担稳定语义的视觉模式。
- 内容资产和 UI 图层的边界。
- 旧设计中互相矛盾的样式和交互。

组件拆解优先级：

1. Tokens：颜色、字体、间距、圆角、阴影。
2. App Shell：状态栏、导航、Header、Sheet。
3. Controls：Button、Input、Chip、Toggle、Slider。
4. Domain Components：Card、Row、Player、Recorder 等。
5. Page Sections：只在少数页面复用的大模块。
6. Screen States：由实例和页面特有图层装配。

输出：完成的 `SOURCE_INVENTORY.md` 和 `COMPONENT_MAP.md`。

### 阶段门

- 页面覆盖数与来源数能对账。
- 每个输出页面都有明确状态名。
- 组件与页面的边界可解释。
- 截图不会被作为最终整页背景。

## 阶段 3：定制化拆解

把用户要求映射到下列决策：

- 视觉品牌：替换或新增哪些 Tokens。
- 信息架构：页面合并、拆分或流程重排。
- 平台：移动端、平板、桌面端及断点。
- 组件：复用现有系统还是建立新组件。
- 内容：语言、文案长度、真实数据和空态。
- 无障碍：字号、对比度、触控区域和焦点顺序。
- 严格数量：页面、组件、变体如何计数。

所有决定先写入 Brief / Component Map，再进入 Blueprint。未得到用户确认但不影响
整体方向的细节可以采用明确记录的合理默认值；会改变产品范围的决定必须确认。

### 阶段门

- “保留 / 改造 / 新增 / 删除”映射已确认。
- 定制项能落到 Token、组件或页面状态。
- 验收条件可以计数或检查。

## 阶段 4：Blueprint 与插件封装

执行：

1. 使用 `npm run new:project` 建立项目目录。
2. 将设计系统写入 `tokens`。
3. 将组件写入 `components`。
4. 将功能流写入 `sections`，页面状态写入 `screens`。
5. 用 `instance` 复用组件，用 Text Layer 名称覆盖文案。
6. 运行 `npm run validate -- <blueprint>`。
7. 若 DSL 无法表达需求，扩展通用 Schema 和渲染器，不加客户专用分支。

### 阶段门

- Schema 校验通过。
- 组件引用、图片引用和 Typography 引用存在。
- 页面数量等于已确认的输出映射。

## 阶段 5：Figma 输出与 QA

在 Figma Desktop 中：

1. 导入 `manifest.json`。
2. 打开 UI Blueprint Builder。
3. 导入并验证 Blueprint。
4. 生成组件和页面。
5. 检查 Variables、Text Styles、组件库和页面 Section。

QA 顺序：

1. 页面 / 状态覆盖率。
2. 组件实例复用率和命名。
3. 图层可编辑性与 Auto Layout。
4. 字体、颜色、间距、图片和矢量。
5. 视觉对照和关键交互状态。
6. 用户要求的严格数量。

交付时报告：

- 来源数量。
- 输出 Section、页面和组件数量。
- 已复用组件。
- 已知差异和仍需人工确认的内容。
- 使用的 Blueprint 路径和运行时版本。
